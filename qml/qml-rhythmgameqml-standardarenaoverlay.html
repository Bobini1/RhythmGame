    Detailed Description

    Use StandardArenaSelectOverlay, StandardArenaGameplayOverlay or StandardArenaResultOverlay for a screen. They supply the default panel and decide when it should appear. This base component provides placement and chat behavior for those overlays.

    Place an overlay directly inside the screen root, or set its visual parent to the item whose coordinates it should use. The viewport property is that parent. Each screen owns its overlay; the game does not add one.

    Replace the panel

    Set panelComponent to your own Component. The loader sizes it to the overlay, but does not inject session or presentation properties. Bind your panel explicitly to the overlay's session and expanded properties. Call setExpanded(bool) when the user changes its size mode, and setChatOpen when the user opens or closes chat.

    An Item property named dragHandle on your panel becomes its move handle. Alternatively, set the overlay's moveHandle. Without either, the panel has no drag handle. Use panel to access the loaded item, checking for null while the overlay is inactive.

    Choose placement and persistence

    The placement frame supplies these additional properties:

    PropertyUse
    defaultPixelRectHintInitial rectangle in the viewport's coordinates, used when no saved rectangle exists.
    minimumPixelSizeMinimum panel size at the 1920 by 1080 design scale; scaled and limited to fit the viewport.
    customizeModeShow move, resize and visibility controls.
    visibilityCustomizableAllow the player to hide the panel. The selection overlay sets this to false.
    themeVarsSettings object used for saved position and preferences; null keeps changes only in memory.
    layoutVariantScreen key used for settings: select, result, k5, k7, k10 or k14. Screen-specific overlays set it for you.

    themeVars defaults to the active profile's settings for layoutVariant. Saved positions are normalized to the viewport size and kept within its bounds. Use z to choose the overlay's stacking order.

    Control visibility and chat

    expanded, overlayVisible and chatSelected are read-only settings. Use setExpanded(bool), setOverlayVisible(bool) and setChatOpen to change them. setChatOpen updates both the session and saved preference; toggleChat switches between chat and standings.

    Hidden or disabled overlays ignore chat actions and shortcuts. The panel can remain loaded while hidden, so use presentationActive when custom panel behavior should run only while it is shown.

    Property Documentation

    active : bool

    Controls whether this screen has an Arena panel.


    chatShortcut : string

    Sets the chat shortcut. The default is F8.


    chatShortcutEnabled : bool

    Enables the chat shortcut while the overlay is presented.


    panel : var [read-only]

    Provides the loaded panel, or null while it is inactive.


    panelComponent : Component [required]

    Supplies the panel's visual content. See the type description for its bindings.


    presentationActive : bool [read-only]

    Reports whether the overlay is active, visible and enabled.


    session : var

    Supplies the Arena state. Defaults to Rg.arenaSession.


    Method Documentation

    setChatOpen(open)

    Opens chat when open is true, or closes it otherwise. Inactive overlays ignore the action.


    toggleChat()

    Toggles chat and saves the choice, when the overlay is presented.
