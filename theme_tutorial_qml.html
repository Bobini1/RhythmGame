2. Use bindings and reusable components

Previous | Tutorial | Next: Profiles and settings

Goal: Change colors with a binding, reuse a button component, and make the menu fit different window sizes.

Install docs/examples/theme-tutorial/02-qml/ and choose it for Main Menu.

Download 02-qml or open the source folder.

Let properties update the screen

A binding is an expression assigned to a QML property with :. When a value used by the expression changes, QML calculates the expression again. Both the background and the accent color depend on the checkbox's checked property in the example.

readonly property color accent: warmColors.checked ? "#e8bc89" : "#a8dcc9"
color: warmColors.checked ? "#30251c" : "#18232e"
Behavior on color {
ColorAnimation { duration: 180 }
}

The checkbox already keeps track of whether it is checked, so the screen can use that value directly. Clicking the checkbox updates both colors through their bindings. The Behavior animates each change to the background color over 180 milliseconds.

CheckBox {
id: warmColors
text: "Use warm colors"
palette.windowText: screen.accent
}

readonly prevents other code from assigning a new value to accent. It doesn't stop the binding from updating. Keep the color expressions as bindings rather than setting the label's color in the checkbox handler. Assigning a value directly to a property replaces any binding that property had.

An id gives an object a name within its QML file. warmColors.checked refers to a property of the checkbox, and actions.openSettings() calls a method on the named standard component.

Use bindings for values that depend on other properties. Use signal handlers for actions, such as opening Settings after a button click.

Put a repeated control in its own file

MenuButton.qml defines a button with a larger font and a consistent height. A QML file whose name begins with a capital letter can be used as a component by neighboring QML files. required means the caller must supply label when it creates the button.

1import QtQuick
2import QtQuick.Controls.FluentWinUI3
3
4// [component]
5Button {
6 id: control
7 required property string label
8 text: control.label
9 font.pixelSize: 20
10 implicitHeight: 48
11}
12// [component]

The menu uses the component four times. Each instance gets its own label and click handler, while the shared file supplies its appearance.

MenuButton {
Layout.fillWidth: true
label: "Song select"
focus: true
onClicked: actions.openSelect()
}
MenuButton {
Layout.fillWidth: true
label: "Multiplayer"
onClicked: actions.openArena()
}
MenuButton {
Layout.fillWidth: true
label: "Settings"
onClicked: actions.openSettings()
}
MenuButton {
Layout.fillWidth: true
label: "Quit"
onClicked: actions.quit()
}

Change the font size in MenuButton.qml and restart. All four buttons should change. Keep helpers and assets in your theme folder. If you want to reuse something from Default, copy it: its private files may change, and other themes may not be installed.

Choose how the screen resizes

Two approaches work well:

  • Scale a fixed canvas. Position controls at a design size, then scale the whole screen to fit. This keeps the proportions of your design.
  • Use layouts. Let RowLayout and ColumnLayout size their children to fit the available space. Use implicitWidth and implicitHeight for natural sizes, and Layout properties for size limits and how extra space is shared.

The first menu scales a fixed 960 by 540 canvas. It keeps the same proportions, leaving unused space when the window has a different aspect ratio.

Item {
id: canvas
width: 960
height: 540
anchors.centerIn: parent
scale: Math.min(screen.width / canvas.width, screen.height / canvas.height)

The second menu's outer layout fills the screen with a margin of 16 pixels. It contains the whole menu between two empty Item objects that act as spacers.

ColumnLayout {
anchors.fill: parent
anchors.margins: 16
spacing: 0

The spacers use Layout.fillHeight and equal Layout.preferredHeight values to share unused height equally. This centers the menu. The outer layout has no spacing, so collapsed spacers leave no gaps in a short window.

Item {
Layout.fillHeight: true
Layout.preferredHeight: 1
}
Item {
Layout.fillHeight: true
Layout.preferredHeight: 1
}

The inner column contains the image, heading, buttons and checkbox. Its maximum height is its natural height, implicitHeight, so extra window height goes to the spacers. Its maximum width is 400, and its children stay 12 pixels apart.

ColumnLayout {
id: menu
Layout.fillWidth: true
Layout.fillHeight: true
Layout.maximumWidth: 400
Layout.maximumHeight: menu.implicitHeight
Layout.alignment: Qt.AlignHCenter
spacing: 12

The image has a preferred height of 120 and can shrink when the menu has less room. Layout.fillHeight lets the layout reduce its height while the controls keep their usual sizes.

Image {
Layout.fillWidth: true
Layout.fillHeight: true
Layout.preferredHeight: 120
Layout.maximumHeight: 120
source: "images/notes.svg"
sourceSize: Qt.size(320, 120)
fillMode: Image.PreserveAspectFit
Accessible.ignored: true
}

A layout controls its immediate children's geometry. Use Layout properties on those children and anchors on the surrounding layout or container. A label needs a constrained width before it can wrap its text.

Try the layout

Try a wide window, a tall window and a short window. The image should stay next to the heading, and the menu should stay centered. In a short window, the spacers collapse and then the image shrinks.

To try a 1:4 split, change the bottom spacer's Layout.preferredHeight to 4. When there is spare height, about one fifth goes above the menu and four fifths below it. The whole menu moves upward, with the image still next to the controls. Qt's layout sizing guide explains how the size limits affect the result.

The checkbox resets when the screen is created again. The next lesson adds a color setting saved in the active profile.
